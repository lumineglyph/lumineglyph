# 03 — CI, dependency updates, branch protection

## Goal

Every pull request and every push to `main` runs a GitHub Actions workflow that:
- type-checks and builds the site
- validates the HTML and checks the links
- enforces Lighthouse score targets
- uploads the built `dist/` as an artifact, which the deploy jobs in steps 06 and 07 reuse

Dependabot keeps npm packages and GitHub Actions up to date. `main` is protected, so changes only land through pull requests that pass CI.

## Why it matters

- **Build once, deploy that exact artifact.** Production gets the same bytes CI tested.
- **Supply-chain basics.** Actions pinned to commit SHAs, minimal token permissions, and a waiting period before adopting new dependency releases.
- **Moena gets a safety net.** A broken edit can't reach production.

## Steps

### A. Make the repo public (decide now)

The repo is currently private on a free plan. On free plans, GitHub only offers these features for **public** repos:
- branch protection and rulesets
- **deployment environments**, which steps 06 and 07 use to scope AWS access

Public repos also get unlimited Actions minutes on standard runners. You'd have to pay for GitHub Pro or Team to get these on a private repo.

The repo contains nothing secret: the Google Form URL is already public on the site, and there are no keys. Before making it public:
1. Agree on it with Moena. It's her repo or your shared org.
2. Look over the git history for anything you wouldn't want public: `git log -p --all | less`, or ask Claude to scan for likely secrets and personal data.
3. Turn on secret scanning and push protection: Settings → Advanced Security.
4. Settings → General → Change visibility → Public.

### B. Workflow

`.github/workflows/pipeline.yml`. Only the build job for now; steps 06 and 07 add deploy jobs to this same file.

```yaml
name: Pipeline

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read          # the default for every job; jobs that need more ask for it

concurrency:
  group: pipeline-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    defaults:
      run:
        working-directory: site
    steps:
      - uses: actions/checkout@<sha> # v7.0.1
        with:
          persist-credentials: false
      - uses: actions/setup-node@<sha> # v7.1.0
        with:
          node-version-file: site/.nvmrc
          cache: npm
          cache-dependency-path: site/package-lock.json
      - run: npm ci
      - run: npx astro check
      - run: npm run build
      - run: npx html-validate "dist/**/*.html"
      # link check: lychee in offline mode (internal links only)  (verify) flags
      # lighthouse: npx lhci autorun
      - uses: actions/upload-artifact@<sha> # v7.0.2
        with:
          name: site-dist
          path: site/dist
          if-no-files-found: error
```

**Pin actions to full commit SHAs**, with the version in a comment. A tag can be moved to point at different code; a SHA can't. To look one up:
```sh
gh api repos/actions/checkout/commits/v7.0.1 --jq .sha
```
Dependabot updates both the SHA and the comment.

**Dev dependencies,** so CI and your machine run the same versions:
```sh
npm i -D html-validate @lhci/cli
```

**HTML validation.** Create `site/.htmlvalidate.json`:
```json
{ "extends": ["html-validate:recommended"] }
```
Run it locally first. If a rule fights with how Astro outputs HTML, turn off that one rule and note why. Don't turn off the whole preset.

**Link check.** Use `lycheeverse/lychee-action` (v2.9) in offline mode against `site/dist`, so every internal link and anchor is checked without calling external sites. You need `--offline` and a `--root-dir` pointing at the absolute `dist` path, so links starting with `/` resolve. **(verify)** the flags against lychee's README. External links like the Google Form are best checked in a separate weekly scheduled job, so a third-party outage doesn't block a PR. That's optional.

**Lighthouse CI.** Create `site/lighthouserc.json`:
```json
{
  "ci": {
    "collect": { "staticDistDir": "./dist", "numberOfRuns": 1 },
    "assert": {
      "assertions": {
        "categories:performance": ["error", { "minScore": 0.95 }],
        "categories:accessibility": ["error", { "minScore": 0.95 }],
        "categories:best-practices": ["error", { "minScore": 0.95 }],
        "categories:seo": ["error", { "minScore": 1 }]
      }
    },
    "upload": { "target": "temporary-public-storage" }
  }
}
```
Notes:
- `temporary-public-storage` gives you a shareable report link in the job log. The reports are public, which is fine here.
- If scores are noisy in CI, raise `numberOfRuns` to 3 rather than lowering the thresholds.

### C. Dependabot

Create `.github/dependabot.yml`:

```yaml
version: 2
updates:
  - package-ecosystem: npm
    directory: /site
    schedule: { interval: weekly }
    cooldown:
      default-days: 7          # wait a week after a release; most malicious packages are caught by then
    groups:
      astro:
        patterns: ["astro", "@astrojs/*"]
  - package-ecosystem: github-actions
    directory: /
    schedule: { interval: weekly }
    cooldown:
      default-days: 7
  # terraform is added in step 04
```

**(verify)** the exact `cooldown` and `groups` syntax against GitHub's Dependabot options reference.

### D. Protect `main`

Settings → Rules → Rulesets → New branch ruleset, targeting the default branch:
- require a pull request before merging
  - Required approvals: 0 is fine for two people. Raise it if you want each other's review.
- require status checks to pass: `build`
- block force pushes and deletion

Repo admins can bypass the rules. Decide whether that includes you, and write the choice in PROGRESS.

## Checkpoint

- A PR with the workflow goes green. Claude reads the run with `gh run view --log` and checks that every step actually ran, not just exited 0.
- Claude checks that each `uses:` is pinned to a 40-character SHA with a version comment, and that `permissions` is `contents: read` at the top level.
- **Negative test.** Push a commit that breaks something: remove a key from `en.json`, or add a link to `#nonexistent`. CI goes red and the PR can't be merged. Then revert it.
- Dependabot appears under Insights → Dependency graph → Dependabot.

## Commit

`ci: build, validate and Lighthouse checks on every PR`, then `chore: dependabot config`.
