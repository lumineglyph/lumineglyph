# 03 — CI, dependency updates, branch protection

## Goal

Every pull request and every push to `main` runs a GitHub Actions workflow that:
- type-checks and builds the site
- validates the HTML
- checks every internal link and `#anchor`
- runs Lighthouse and fails if a score drops below target
- uploads the built `dist/` as an artifact, which the deploy jobs in steps 06 and 07 reuse

Dependabot keeps npm packages and GitHub Actions up to date. `main` is protected, so changes only land through pull requests that pass CI.

## Why it matters

- **Build once, deploy that exact artifact.** Production gets the same bytes CI tested.
- **Supply-chain basics.** Actions are pinned to commit SHAs, the workflow token can only read, and new dependency releases wait a week before Dependabot proposes them.
- **Moena gets a safety net.** A broken edit can't reach production.

**3. Create `site/lighthouserc.json`:**
```json
{
  "ci": {
    "collect": {
      "staticDistDir": "./dist",
      "url": ["http://localhost/", "http://localhost/en/", "http://localhost/works/", "http://localhost/en/works/"],
      "numberOfRuns": 3
    },
    "assert": {
      "assertions": {
        "categories:performance": ["error", { "minScore": 0.95, "aggregationMethod": "median-run" }],
        "categories:accessibility": ["error", { "minScore": 1 }],
        "categories:best-practices": ["error", { "minScore": 1 }],
        "categories:seo": ["error", { "minScore": 1 }]
      }
    },
    "upload": { "target": "temporary-public-storage" }
  }
}
```

JSON can't hold comments, so here's what each part does:
- **`staticDistDir`:** Lighthouse CI serves `dist/` itself, with gzip like CloudFront will. It swaps in its own port, so the URLs don't need one.
- **`url`:** the four real pages. Without this list it would audit the first five HTML files it finds, including the 404 page. html-validate and lychee still check the 404 page.
- **Performance:** each page runs 3 times, and the check uses the middle run (`median-run`). The default is the best run, which would hide a real slowdown. The target stays 95.
- **Accessibility, best practices and SEO:** 100 (`1`). They're 100 now and don't vary between runs, so anything lower is a real regression. If a Chrome update ever lowers best practices for reasons outside your control, lower that one to `0.95` and note why in PROGRESS.
- **`temporary-public-storage`:** the job log prints a link to the full report. Reports are public and deleted after a few days, which is fine for a public site.

### C. Write the workflow

Create `.github/workflows/pipeline.yml` at the **repo root**, not in `site/`. Steps 06 and 07 add their deploy jobs to this same file.

```yaml
name: Pipeline

on:
  pull_request:
  push:
    branches: [main]

# The default token for every job: read the repo, nothing else.
# Jobs that need more (the deploy jobs in steps 06 and 07) ask for it themselves.
permissions:
  contents: read

# A new push to a PR cancels that PR's older, still-running pipeline. Runs on main never cancel.
concurrency:
  group: pipeline-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  build:
    name: build # the name branch protection requires (step G)
    runs-on: ubuntu-24.04 # a fixed image rather than ubuntu-latest, so it doesn't change under us
    timeout-minutes: 15
    defaults:
      run:
        working-directory: site
    steps:
      - name: Check out the repo
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false # don't leave the token in .git/config for later steps

      - name: Set up Node
        uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version-file: site/.nvmrc
          cache: npm
          cache-dependency-path: site/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Type-check
        run: npm run check

      - name: Build
        run: npm run build

      - name: Validate HTML
        run: npx html-validate "dist/**/*.html"

      # Internal links and #anchors only. --offline skips external sites, so another site
      # being down can't block a PR. --root-dir resolves links that start with "/".
      - name: Check internal links
        uses: lycheeverse/lychee-action@e7477775783ea5526144ba13e8db5eec57747ce8 # v2.9.0
        with:
          args: >-
            --offline
            --no-progress
            --include-fragments
            --index-files index.html
            --root-dir ${{ github.workspace }}/site/dist
            site/dist

      - name: Lighthouse
        run: npx lhci autorun

      - name: Upload the built site
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: site-dist
          path: site/dist
          if-no-files-found: error
          retention-days: 7
```

Notes:
- **Why the long SHAs.** A tag like `v7.0.1` can be moved to point at different code, but a commit SHA can't. The comment records the version for people, and Dependabot updates both. Step A.5 makes GitHub reject any action that isn't pinned this way. To look up a SHA yourself:
  ```sh
  gh api repos/actions/checkout/commits/v7.0.1 --jq .sha
  ```
- **The lychee step has no `working-directory`.** `defaults.run` only applies to `run:` steps, not `uses:` steps, so lychee runs from the repo root and its paths start with `site/`.
- **Order matters.** Each step only runs if the earlier ones passed, so the cheapest checks go first and Lighthouse, the slowest, goes last.

### D. Dependabot

Create `.github/dependabot.yml`:

```yaml
version: 2
updates:
  - package-ecosystem: npm
    directory: /site
    schedule:
      interval: weekly
    # Wait 7 days after a release before proposing it. Most malicious releases are caught and
    # pulled within days. Security fixes skip this wait.
    cooldown:
      default-days: 7
    commit-message:
      prefix: chore # → "chore(deps): bump …" and "chore(deps-dev): bump …"
      include: scope
    # One PR per group instead of one per package
    groups:
      astro:
        patterns: ["astro", "@astrojs/*"]
      fontsource:
        patterns: ["@fontsource/*"]
    # @astrojs/check (the type checker) supports TypeScript 5 and 6 only (0.9.12, checked 2026-11-18).
    # Remove this once a release supports 7: `npm view @astrojs/check peerDependencies`.
    # (Added after the first Dependabot run proposed TypeScript 7 and CI failed on `npm ci`.)
    ignore:
      - dependency-name: typescript
        update-types: ["version-update:semver-major"]

  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
    cooldown:
      default-days: 7
    commit-message:
      prefix: ci # → "ci: bump actions/checkout …"
  # terraform is added in step 04
```
